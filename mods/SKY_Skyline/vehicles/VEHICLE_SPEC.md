# Drivable bus and garbage truck: modeller and rigger spec (D64)

**Status: blocked on a modeller. Nothing here is packed into the mod.**

## Why this is not generated

A DayZ car is a `CarScript` (4_world/entities/vehicles/carscript.c). Bohemia's vehicle physics drives it from
three things that must agree with one another:
- the **model**: Geometry with wheel components, a Geometry PhysX LOD, named selections, memory points for the
  wheels, axles, dampers, seats and lights, and proxies for the crew and the attachments;
- its **model.cfg**: the skeleton bones and the animations driven by the wheel, steering, door and damper sources;
- the **config**: `SimulationModule` (engine, gearbox, axles and wheels referring to the memory points),
  `Crew`, `DamageSystem` zones, `AnimationSources`, `attachments[]` and `GUIInventoryAttachmentsProps`.

The vanilla vehicles' model.cfg and P3D are binarized inside the game data. They are not in the script
sources this project can read, so a generated model cannot be guaranteed to match the names the vanilla
simulation expects. A mismatch makes a car that spawns but does not drive, or that falls through the
ground. The project only ships what it can verify, so the drivable versions go to a modeller with this spec.

## Pipeline for the modeller (Windows, DayZ Tools, P: mounted)

1. Pick the donor: **Truck_01 (V3S)** for both vehicles. It has the right size class, 6 wheels and twin rears.
   The vanilla script is `Truck_01_Base` (truck_01_base.c): V3S anim instance, seats and lights.
2. Read the donor's model.cfg / named selections on `P:\DZ\vehicles\wheeled\truck_01\` (or unpack the data PBO
   with DayZ Tools and open the model in Object Builder). Copy its skeleton, bone and selection names
   **exactly**. Do not rename them to ours.
3. Open `reference/sky_ref_*.p3d` and rebuild them over the donor's LOD structure:
   - Res LODs from our bodies;
   - Geometry (with mass), Geometry PhysX, Fire Geometry, View Geometry, Memory and LandContact LODs from the
     donor's proportions, scaled to our wheelbase.
   - Our reference uses these names (rename them to the donor's):

   | Ours | Meaning |
   |---|---|
   | `wheel_<side>_<axle>` (side 1 = left / -X, 2 = right / +X; axle 1 = front) | Wheel mesh |
   | `wheel_<side>_<axle>_axis` (2 memory points) | Rotation axis |
   | `wheel_<side>_<axle>_damper`, `_damper_land` | Suspension travel |
   | `door_driver`, `door_codriver` (truck), `door_0..2` (bus, +X side) | Doors |
   | `light_front`, `light_rear` | Lamp faces (hiddenSelections for the lit material) |
   | `glass`, `body`, `mirror` | Glass, body and mirror faces |

4. Textures: paint the body with the SKY palette. Bus: faded yellow `fair` band + white roof. Truck: municipal
   green body + white cab.
5. Fill in `templates/sky_vehicles_config.cpp.txt`: model paths, `SimulationModule` copied from the vanilla V3S
   config (`P:\DZ\vehicles\wheeled\truck_01\config.cpp`), adjusted for mass and wheelbase. Then move the
   config into a new PBO `addons/sky_vehicles`, and the script template into
   `sky_scripts/scripts/4_World/SKY/SKY_Vehicles.c`.
6. Add the CE entries: vehicle events like vanilla `VehicleTruck01`, in a SKY events file.
7. Test with TESTING §29.

## Hypotheses (PENDING_VERIFICATION)

- P30: the V3S skeleton can carry a 11.4 m bus body. The wheelbase changes, so the axle memory points move and
  the PhysX geometry is rebuilt.
- P31: the V3S simulation config (gear ratios, torque, braking) is acceptable for an empty city bus and a
  garbage truck at their masses (bus ~ 8 t, truck ~ 9 t). Tune `SimulationModule` after the first drive.
